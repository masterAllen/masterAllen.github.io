记录：包装 esptool GUI

本地编辑 | 打开本地目录 | 复制路径

需要给客户提供升级工具，虽然 ESP32 官方提供了对应 exe，但会显示具体芯片，在网上找到 GUI 工具背后的源码，很幸运 ESP32 官方将其开源，所以可以直接下载下来在命令行使用。

所以之后我们要做的就是写一个 GUI 界面即可，但其实中间还是遇到了一些坑，特此记录一下。

1. 实现调用代码升级

下载完源码后，首先就要先实现调用代码升级，才能之后把他包装成 GUI 界面。

python esptool.py 后面还需要很多参数，即使看官方文档也很有可能漏掉，估计会消耗很多时间。这里我觉得很巧妙，直接使用 Arduino IDE 进行固件烧写，然后他的下方终端有一些输出信息，发现他其实也用的是 esptool，所以这样我们就能从这些输出信息中获取到需要传入的参数。

2. 外部代码中传入这些参数

然后我们要写一个 GUI 代码，里面调用 esptool.py 的方法，但需要知道传入的参数是怎么传的。

分析他的代码结构即可，也很容易分析，其最后到了 esptool/__init.py__ 文件的 main 方法，里面有如下语句：

    argv = expand_file_arguments(argv or sys.argv[1:])
    args = parser.parse_args(argv)

都已经为我们贴心准备了。我们只需要第一次在这里加入 print(argv)，然后执行命令行操作，看看最终的 argv 是什么，发现是一个列表，那外部 GUI 代码就先构造这个列表，然后作为参数传进去即可。

3. 像串口助手一样自动检测串口列表，并更新

使用下面代码即可，有一些库可以直接用来检测串口

# 获取所有可用的串口
def get_ports():
    ports = serial.tools.list_ports.comports()
    result = [port.device for port in ports]
    return result

# 更新下拉框
def update_combobox():
    options = get_ports()
    combobox['values'] = options  # 更新下拉框的选项

    now_option = combobox.get()
    if now_option not in set(options):
        now_option = options[0] if len(options) > 0 else ''  # 默认选择第一个选项

    combobox.set(now_option)

    # 每隔1000毫秒（1秒）重新调用 update_combobox
    root.after(1000, update_combobox)
update_combobox()

4. 出错会直接退出

发现 GUI 调用的时候，如果烧录出错（比如 COM 口选择错），会直接退出，即使 GUI 主程序代码使用 try-except 也不行。

后来发现是 esptool.py 中使用 sys.exit() 退出了，所以需要捕获 sys.exit 函数：

    try:
        esptool._main(argv)
        action_button.config(text="升级完成")
        messagebox.showinfo("Success", "固件升级成功")
    except SystemExit as e:
        messagebox.showerror("Error", str(e))

而在 esptool 源码中，修改 sys.exit() 的参数，这样弹窗也能显示具体信息了：

    try:
        main()
    except esptool.FatalError as e:
        log.error(f"\nA fatal error occurred: {e}")
        # 原来时 sys.exit(1)
        sys.exit(e)

5. 打包 GUI 界面时显示 No JSON Found

使用 nuitka 打包时，显示 No JSON Found，在网上也没有找到对应措施。后来是在源码搜索 "not found" 找到对应源码才明白是为什么，具体在 loder.py 文件中。

class StubFlasher:
    STUB_DIR = os.path.join(os.path.dirname(__file__), "targets", "stub_flasher")
    # directories will be searched in the order of STUB_SUBDIRS
    STUB_SUBDIRS = ["1", "2"]

    def __init__(self, chip_name):
        with open(self.get_json_path(chip_name)) as json_file:
            stub = json.load(json_file)

        # ...

    def get_json_path(self, chip_name):
        chip_name = strip_chip_name(chip_name)
        for i, subdir in enumerate(self.STUB_SUBDIRS):
            json_path = os.path.join(self.STUB_DIR, subdir, f"{chip_name}.json")
            # ...

可以看到，这里他会使用 get_json_path 动态导入 JSON 文件，所以打包的时候就没有把最后要导入的文件打包进去，所以就会显示 No JSON Found。

解决方法就是这里直接改成静态导入，因为我们的芯片是固定的，所以这里 get_json_path 返回的文件是固定的。

class StubFlasher:
    STUB_DIR = os.path.join(os.path.dirname(__file__), "targets", "stub_flasher")
    # directories will be searched in the order of STUB_SUBDIRS
    STUB_SUBDIRS = ["1", "2"]

    def __init__(self, chip_name):
        with open('固定的路径（可以先print然后执行看看是哪一个）') as json_file:
            stub = json.load(json_file)

        # ...

    # 没有用了，直接注释掉
    # def get_json_path(self, chip_name):
    #     chip_name = strip_chip_name(chip_name)

6. 打包时间很长，GUI 界面会卡顿

这也是经典问题了，如果是 QT 那就直接用 QThread。但这里我图轻量，用的 tkinter，一开始是用的 tkinter 叫做 after 的函数，但感觉还是乱。

后来我干脆修改 esptool.py 源码了。搜索其更新过程的输出文本，定位到源码的位置，后来发现主要慢的地方是 log.set_progress 那里，从 0% 到 100% 挺慢的，进一步定位，发现在 esptool/logger.py 文件中：

    def set_progress(self, percentage: float):
        """
        Sets the progress of long-running operations to a specific percentage.
        Overwrite this method in a custom logger to implement e.g. a progress bar.

        Percentage is a float between 0 and 100.
        """
        pass

可以看到，他是空着的。我们可以直接用，所以我们将这个 log 对象和我们的 button 绑定，然后执行 set_progress 时候，直接修改 button 的文本。

# esptool/logger.py
    def set_progress(self, percentage: float):
        self.percentage = percentage
        if 0 < percentage < 100:
            self.button.config(text=f'正在升级... {self.percentage}%')

    def set_button(self, button):
        self.button = button

# main.py
# 按下按钮后
def on_button_click():
    # ...
    import esptool
    from esptool.logger import log
    log.set_button(action_button)

    esptool.run(argv)

但发现并没有起作用。后来终于明白了：主程序 GUI 是始终卡住的。如果要让按钮的文本更新，那么需要 on_button_click 执行完毕后，才会刷新。

所以这里就用多线程来完成：

def on_button_click():
    # ... 构建 argv
    threading.Thread(target=run_esptool, args=(argv,), daemon=True).start()

# 多线程中执行 esptool，这样 esptool 里面如果修改了 button 文本，那么主线程也会及时刷新
def run_esptool(argv):
    import esptool
    from esptool.logger import log
    log.set_button(action_button)

    action_button.config(state=tk.DISABLED)
    action_button.config(text="正在升级...")

复盘

  1. 打包时先不要 disable-console，不要图快
  2. 打包时如果代码中有静态加载文件的（即源码中加载的是固定的文件链接），可以放心了。最后打包会自动将文件打包到 exe 中。

  3. 打包时如果代码中有动态加载文件的，打包后执行可能就有问题。最好就是在源码处打印一下，看看究竟加载的什么文件。

    1. 如果始终固定，那么就写死路径改成静态加载；

  4. 如果文件不一定是唯一的，那就打消打包成一个文件的想法吧，老老实实在当前 exe 文件中新建目录，把那些配置文件放进去，然后修改源码，让他加载文件时从当前 exe 目录加载这些文件。
