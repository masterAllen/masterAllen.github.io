给 ESP32 增加串口有线 OTA 功能

本地编辑 | 打开本地目录 | 复制路径

ESP32 自带很方便的无线 OTA 调用接口，但是现在我们需要有线 OTA，所以要在其基础上修改。

很明显，既然可以无线，那么一定可以有线，因为核心其实不是“无线下载”，而是：在设备运行期间，将新的应用固件写入非当前运行的应用分区，再切换启动分区。

固件数据从哪里来并不重要。它可以来自 HTTP、蓝牙、SD 卡，也可以来自 UART 串口。

本文主要介绍 ESP32 固件端的修改。上位机只负责按照约定的数据格式发送固件，不是本文重点。

一、实现原理

ESP32 的 OTA 分区表通常包含两个应用分区，例如 ota_0 和 ota_1。设备从其中一个分区运行时，可以把新固件写入另一个分区。

有线 OTA 的整体流程如下：

正常运行并监听串口
        ↓
识别 OTA 启动命令
        ↓
取得下一个 OTA 应用分区
        ↓
初始化 OTA 写入
        ↓
串口接收固件数据帧
        ↓
检查包序号和 CRC
        ↓
逐包写入备用分区
        ↓
收到结束帧
        ↓
结束并校验 OTA 镜像
        ↓
设置新启动分区并重启

真正完成 Flash 写入和分区切换的，是 ESP-IDF 提供的几个接口：

esp_ota_get_next_update_partition();
esp_ota_begin();
esp_ota_write();
esp_ota_end();
esp_ota_set_boot_partition();

我们需要增加的主要逻辑，是把现有串口通信与这些接口连接起来。

二、准备支持 OTA 的分区表

有线只是固件的传输方式，ESP32 最终仍然依赖 OTA 分区机制。因此，工程使用的 Partition Scheme 必须包含 OTA 数据分区以及至少两个应用分区。

程序中可以遍历应用分区，检查当前 Flash 中是否存在 ota_0 和 ota_1：

void check_ota_partitions() {
    const esp_partition_t *part;
    esp_partition_iterator_t it = esp_partition_find(
        ESP_PARTITION_TYPE_APP,
        ESP_PARTITION_SUBTYPE_ANY,
        NULL
    );
    bool found_ota = false;

    while (it != NULL) {
        part = esp_partition_get(it);
        if (part->subtype == ESP_PARTITION_SUBTYPE_APP_OTA_0 ||
            part->subtype == ESP_PARTITION_SUBTYPE_APP_OTA_1) {
            DEBUG_PRINT(
                "Found OTA partition: %s, address: 0x%x, size: %d bytes\n",
                part->label,
                part->address,
                part->size
            );
            found_ota = true;
        }
        it = esp_partition_next(it);
    }

    if (!found_ota) {
        DEBUG_PRINT("No OTA partitions found.\n");
    }
}

如果设备只有一个应用分区，就没有安全的位置写入下一版应用，后面的 OTA 代码也无法正常工作。

三、设计一套简单的串口升级协议

为了让正常业务数据和 OTA 数据可以共用串口，我定义了三种帧：启动帧、固件数据帧和结束帧。

1. 启动帧

00 64 00 1A CRC_L CRC_H
  • 00 64：OTA 启动标识。
  • 00 1A：设备 ID，其中 1A 是举的例子。
  • 最后两个字节：CRC16。

2. 固件数据帧

00 65 SEQ_H SEQ_L DATA[256] CRC_L CRC_H
  • 00 65：数据帧标识。
  • SEQ_H SEQ_L：从 0 开始递增的 16 位包序号，采用大端顺序。
  • DATA[256]：固件数据，每包固定 256 字节。
  • CRC_L CRC_H：整帧的 CRC16，低字节在前。

一个完整的数据帧长度为：

2 字节帧头 + 2 字节序号 + 256 字节固件 + 2 字节 CRC = 262 字节

3. 结束帧

00 66 COUNT_H COUNT_L CRC_L CRC_H

结束帧中的 COUNT 表示本次发送的数据包总数。ESP32 会用它与实际成功写入的包数进行比较。

数据帧采用 CRC16 校验，当前算法的初始值为 0xFFFF，多项式为 0xA001。CRC 可以发现串口传输中的大部分误码；包序号则用于发现丢包、重复包和乱序。

四、从正常串口通信切换到 OTA 模式

ESP32 平时仍然按照原有方式处理业务数据。只有检测到 OTA 启动帧时，才进入固件接收流程。

当前实现使用 is_OTA_header() 判断帧头和设备 ID，每次收到一个数据包，都会判断一下，如果符合条件，那么进入 OTA 模式：

bool is_OTA_header(std::vector<uint8_t>& buffer) {
    if (buffer.size() == OTA_HEADER_SIZE) {
        if (buffer[0] == 0x00 &&
            buffer[1] == 0x64 &&
            buffer[2] == 0x00 &&
            buffer[3] == DEVICE_ID) {
            return true;
        }
    }
    return false;
}

五、根据帧头读取不同长度的数据

进入 OTA 模式后，ESP32 只需要处理数据帧 0x0065 和结束帧 0x0066。

数据帧是固定长度，但结束帧只有 6 字节。因此，接收函数先读取两个字节的帧头，再决定还需要读取多少数据：

int OTArecv(HardwareSerial &nowSerial, uint8_t *buffer, int wantsize)
{
    int now_bytes = nowSerial.readBytes(buffer, 2);
    if (now_bytes != 2) {
        return -1;
    }

    if (buffer[0] == 0x00 && buffer[1] == 0x66) {
        // 结束帧总长度为 6 字节
        wantsize = 6;
    } else if (buffer[0] != 0x00 || buffer[1] != 0x65) {
        DEBUG_PRINT("NOT 0x0065, clear: %02X %02X ",
                    buffer[0], buffer[1]);
        while (nowSerial.available()) {
            DEBUG_PRINT("%02X ", nowSerial.read());
        }
        DEBUG_PRINT("\n");
        return -1;
    }

    now_bytes = nowSerial.readBytes(buffer + 2, wantsize - 2);
    if (now_bytes != wantsize - 2) {
        DEBUG_PRINT("recv not enough data, want=%d, now=%d\n",
                    wantsize, now_bytes + 2);
        while (nowSerial.available()) {
            DEBUG_PRINT("%02X ", nowSerial.read());
        }
        DEBUG_PRINT("\n");
        return -1;
    }

    return wantsize;
}

readBytes() 会等待指定数量的数据或等待到串口超时。读取长度不正确时，本次数据会被视为无效帧。

六、初始化 OTA 写入

开始进行 OTA，首先获取当前运行分区之外的下一个升级分区：

const esp_partition_t *ota_partition =
    esp_ota_get_next_update_partition(NULL);

if (ota_partition == NULL) {
    DEBUG_PRINT("OTA partition not found\n");
    return;
}

随后调用 esp_ota_begin() 初始化写入：

esp_ota_handle_t ota_handle;

esp_err_t err = esp_ota_begin(
    ota_partition,
    OTA_SIZE_UNKNOWN,
    &ota_handle
);

if (err != ESP_OK) {
    DEBUG_PRINT("esp_ota_begin failed: %s\n", esp_err_to_name(err));
    return;
}

DEBUG_PRINT("ota_partition: %s\n", ota_partition->label);

这里使用 OTA_SIZE_UNKNOWN，表示 ESP32 在开始写入时不依赖上位机提前发送固件总字节数。

到这一步，备用 OTA 分区已经准备好，可以开始接收并写入固件。

七、校验数据并写入 OTA 分区

ESP32 使用 packet_num 记录下一包期望收到的序号：

uint16_t packet_num = 0;

接收到 0x0065 数据帧后，先从第 3、4 字节取出包序号：

uint16_t now_num = (buffer[2] << 8) | buffer[3];

if (now_num != packet_num) {
    continue;
}

序号正确后，再检查整帧 CRC：

if (!check_crc(buffer, bytes_received)) {
    DEBUG_PRINT("Received bin data crc incorrect\n");
    continue;
}

数据帧前 4 字节是帧头和包序号，最后 2 字节是 CRC，所以真正的固件内容长度为：

bytes_received - 6

校验全部通过后，提取固件内容并写入 OTA 分区：

uint8_t bin_data[bytes_received - 6];
memcpy(bin_data, buffer + 4, bytes_received - 6);

err = esp_ota_write(
    ota_handle,
    bin_data,
    bytes_received - 6
);

if (err != ESP_OK) {
    DEBUG_PRINT("esp_ota_write failed: %s\n", esp_err_to_name(err));
    free(buffer);
    esp_ota_end(ota_handle);
    return;
}

resetOtaActivity();
packet_num++;

这里没有先把整个固件保存到 RAM，而是收到一包、校验一包、写入一包。无论固件有多大，ESP32 都只需要保留一个数据帧大小的接收缓冲区。

完整的接收循环如下：

while (true) {
    bytes_received = OTArecv(nowSerial, buffer, wantsize);

    if (bytes_received <= 0) {
        // 让出 CPU，保证超时监控任务可以运行
        delay(100);
        continue;
    }

    if (buffer[0] == 0x00 && buffer[1] == 0x65) {
        uint16_t now_num = (buffer[2] << 8) | buffer[3];

        if (now_num != packet_num) {
            continue;
        }

        if (!check_crc(buffer, bytes_received)) {
            continue;
        }

        uint8_t *bin_data = buffer + 4;
        int bin_size = bytes_received - 6;

        err = esp_ota_write(ota_handle, bin_data, bin_size);
        if (err != ESP_OK) {
            free(buffer);
            esp_ota_end(ota_handle);
            return;
        }

        resetOtaActivity();
        packet_num++;
    }
    else if (buffer[0] == 0x00 && buffer[1] == 0x66) {
        uint16_t received_count = (buffer[2] << 8) | buffer[3];

        if (!check_crc(buffer, bytes_received) ||
            received_count != packet_num) {
            continue;
        }

        resetOtaActivity();
        break;
    }
}

上面把 buffer + 4 直接作为固件数据指针传给 esp_ota_write()，与原实现先复制到临时数组再写入的效果相同，也更容易看清每个字段的关系。

八、结束写入并切换启动分区

收到合法的 0x0066 结束帧后，固件数据已经全部写入备用分区。接下来调用 esp_ota_end() 结束本次 OTA：

err = esp_ota_end(ota_handle);
if (err != ESP_OK) {
    DEBUG_PRINT("esp_ota_end failed: %s\n", esp_err_to_name(err));
    return;
}

esp_ota_end() 不只是关闭写入句柄，还会检查写入的应用镜像是否合法。只有它返回 ESP_OK，才继续切换启动分区：

err = esp_ota_set_boot_partition(ota_partition);
if (err != ESP_OK) {
    DEBUG_PRINT(
        "esp_ota_set_boot_partition failed: %s\n",
        esp_err_to_name(err)
    );
    return;
}

DEBUG_PRINT("Restarting...\n");
esp_restart();

重启后，ESP32 Bootloader 会从刚写入的 OTA 分区启动，新固件正式生效。

九、增加 OTA 超时恢复

串口线可能被拔掉，上位机也可能在传输过程中退出。如果接收循环一直等待，设备就会长期停留在 OTA 模式。

为此，我增加了一个 FreeRTOS 监控任务。每次成功处理数据帧时更新活动时间；如果 60 秒没有有效 OTA 数据，就自动重启设备：

#define OTA_TIMEOUT_MS        60000
#define OTA_CHECK_INTERVAL_MS 1000

static bool otaInProgress = false;
static unsigned long lastOtaActivity = 0;

void resetOtaActivity() {
    lastOtaActivity = millis();
}

void checkOtaActivity(void *parameter) {
    while (otaInProgress) {
        if (millis() - lastOtaActivity > OTA_TIMEOUT_MS) {
            DEBUG_PRINT("OTA activity timeout, restart...\n");
            SerialDebug.flush();
            delay(1000);
            ESP.restart();
        }

        vTaskDelay(pdMS_TO_TICKS(OTA_CHECK_INTERVAL_MS));
    }

    vTaskDelete(NULL);
}

进入 perform_OTA() 时启动监控：

otaInProgress = true;
lastOtaActivity = millis();

xTaskCreate(
    checkOtaActivity,
    "otaCheck",
    2048,
    NULL,
    1,
    NULL
);

接收失败后还需要短暂调用 delay()，让 FreeRTOS 调度其他任务：

if (bytes_received <= 0) {
    delay(100);
}

这样即使传输被意外中断，设备也能在超时后通过重启回到正常工作状态。

十、perform_OTA() 的完整结构

把前面的步骤组合起来，ESP32 端的 OTA 主函数可以概括为：

void perform_OTA(HardwareSerial &nowSerial, int wantsize)
{
    otaInProgress = true;
    lastOtaActivity = millis();
    xTaskCreate(checkOtaActivity, "otaCheck", 2048, NULL, 1, NULL);

    const esp_partition_t *ota_partition =
        esp_ota_get_next_update_partition(NULL);
    if (ota_partition == NULL) {
        return;
    }

    esp_ota_handle_t ota_handle;
    esp_err_t err = esp_ota_begin(
        ota_partition,
        OTA_SIZE_UNKNOWN,
        &ota_handle
    );
    if (err != ESP_OK) {
        return;
    }

    uint8_t *buffer = (uint8_t *)malloc(wantsize);
    if (buffer == NULL) {
        return;
    }

    uint16_t packet_num = 0;

    while (true) {
        int bytes_received = OTArecv(nowSerial, buffer, wantsize);
        if (bytes_received <= 0) {
            delay(100);
            continue;
        }

        if (buffer[0] == 0x00 && buffer[1] == 0x65) {
            uint16_t now_num = (buffer[2] << 8) | buffer[3];
            if (now_num != packet_num ||
                !check_crc(buffer, bytes_received)) {
                continue;
            }

            err = esp_ota_write(
                ota_handle,
                buffer + 4,
                bytes_received - 6
            );
            if (err != ESP_OK) {
                free(buffer);
                esp_ota_end(ota_handle);
                return;
            }

            packet_num++;
            resetOtaActivity();
        }
        else if (buffer[0] == 0x00 && buffer[1] == 0x66) {
            uint16_t received_count = (buffer[2] << 8) | buffer[3];
            if (!check_crc(buffer, bytes_received) ||
                received_count != packet_num) {
                continue;
            }

            resetOtaActivity();
            break;
        }
    }

    free(buffer);

    err = esp_ota_end(ota_handle);
    if (err != ESP_OK) {
        return;
    }

    err = esp_ota_set_boot_partition(ota_partition);
    if (err != ESP_OK) {
        return;
    }

    esp_restart();
}

这段代码展示的是主干流程。实际工程中的日志输出和错误处理可以根据项目需要保留。

十一、上位机需要做什么

上位机逻辑并不复杂，只需要完成以下工作：

  1. 以 115200 波特率打开串口。
  2. 发送 0x0064 OTA 启动帧。
  3. 读取 .bin 文件，并按 256 字节分包。
  4. 为每包添加 0x0065 帧头、递增序号和 CRC16。
  5. 全部发送完成后，发送 0x0066 结束帧和总包数。

项目中使用 Python 和 pyserial 实现了命令行与 GUI 两个版本。上位机本质上只是固件数据源，真正的 OTA 逻辑都在 ESP32 端完成。

十二、当前方案的边界

这套实现已经可以完成基本的串口有线 OTA，但它仍是一套简单协议：

  • 当前没有逐包 ACK/NACK 和自动重传；某包校验失败后，上位机不会自动补发。
  • OTA 启动检测目前只检查帧头和设备 ID，没有在 is_OTA_header() 中检查启动帧 CRC。
  • 上位机最后一包使用 0x00 补齐，协议没有单独携带固件真实字节数。
  • CRC 用于发现传输错误，不等于固件签名或身份认证。

如果用于现场批量升级或对可靠性要求较高的产品，下一步应补充应答重传、固件真实长度、整包哈希或签名校验等机制。不过对于受控环境下通过数据线升级设备，这套方案已经完成了从串口接收固件到 OTA 分区启动的完整闭环。

总结

ESP32 的 OTA 并不依赖 Wi-Fi。只要能把新的应用镜像可靠地送到设备端，就可以利用 ESP-IDF 的 OTA API 完成升级。

这次修改的关键点可以归纳为四步：

  1. 在原有串口协议中增加 OTA 启动命令。
  2. 将固件拆成带序号和 CRC 的固定长度数据帧。
  3. ESP32 校验数据后调用 esp_ota_write() 逐包写入备用分区。
  4. 接收完成后调用 esp_ota_end()、esp_ota_set_boot_partition() 和 esp_restart() 让新固件生效。

通过这种方式，即使设备没有连接网络，也可以直接通过 USB 串口线完成固件更新，这就是串口有线 OTA 的基本实现思路。
